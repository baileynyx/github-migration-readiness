# Verify Git refs before accepting a migration

`verify_refs.py` compares two saved branch/tag advertisements offline. It identifies missing refs, destination-only refs and changed object IDs. An annotated tag's object and peeled target are separate records: recreating its annotation is a difference even if the target commit stays the same.

## Run the local rehearsal

[Watch the 30-second visualization](../README.md#watch-the-30-second-evidence-walkthrough), read its [text version](assets/ref-demo/transcript.md), or follow the [image reproduction instructions](ref-demo.md).

From the repository root, with Python 3.11+ and Git installed:

```shell
python rehearse_refs.py --output-dir reports/ref-rehearsal
```

Choose a new output directory each time. The script creates two temporary bare Git repositories, captures their actual advertisements and invokes the comparator CLI. It checks an intact copy, then deliberately changes only the disposable destination. Network transports are disabled and inherited Git configuration is isolated. Temporary repositories are removed after the run; synthetic captures, both reports and timestamped `evidence.json` remain in the output directory.

| Scenario | Matched | Missing | Unexpected | Mismatched | Comparator exit |
| --- | ---: | ---: | ---: | ---: | ---: |
| Intact copy | 5 | 0 | 0 | 0 | 0 |
| Deliberately changed copy | 2 | 1 | 1 | 2 | 1 |

The second scenario deletes `feature`, adds `destination-only`, moves `main` and recreates the annotated tag with a different message. The lightweight tag and peeled target still match. The rehearsal itself returns 0 only when both expected outcomes and unchanged source refs are confirmed; failure returns 2.

Read the committed [difference report](../examples/ref-verification/refs.md) or reproduce it:

```shell
python verify_refs.py examples/ref-verification/source.refs examples/ref-verification/destination.refs --output-dir reports/ref-example
```

This example returns **1 intentionally**. Inspect `$LASTEXITCODE` in PowerShell or `$?` in Bash immediately afterward. The JSON and Markdown files are written before the difference exit. The examples are synthetic captures generated by the rehearsal, not evidence of a live migration.

## Capture evidence for an authorized comparison

Use independently collected source and destination advertisements during an agreed write freeze. Record repository identities, access scope, capture time, Git version and successful command exit in a controlled acceptance record. Local clones expose their own local branches; they are not automatically complete views of the hosted repositories.

For each approved repository path or remote, save the complete stdout of `git ls-remote --heads --tags` as a separate UTF-8 file. Preserve the tab between object ID and ref name. Do not add patterns, filter records, merge stderr into the file, or use `--refs`, which suppresses peeled tag records. `--heads` remains a compatibility alias; current Git calls it `--branches`. See [Git's output and option contract](https://git-scm.com/docs/git-ls-remote).

Keep real captures under ignored `runtime/` and reports under ignored `reports/`, with access appropriate to their contents. Once `runtime/source.refs` and `runtime/destination.refs` have been captured successfully:

```shell
python verify_refs.py runtime/source.refs runtime/destination.refs --output-dir reports/ref-cutover
```

An unsuccessful collection must be investigated before comparison. The tool cannot tell whether two valid-looking files came from the intended repositories, whether permissions hid refs, or whether both captures omitted peeled records. File hashes identify the exact supplied bytes; they do not authenticate their origin.

## Input and gate contract

| Exit | Meaning | Action |
| --- | --- | --- |
| 0 | Nonempty supplied ref sets match exactly | Continue the remaining acceptance checks |
| 1 | Missing, unexpected or mismatched records | Investigate each difference and preserve destination-only work |
| 2 | Invalid/inconclusive input or input/output failure | Correct collection or output conditions; do not treat as a match |

Inputs are limited to 10 MiB each. SHA-1 and SHA-256 object IDs are supported, but cannot be mixed within or between nonempty captures. Names are case-sensitive and must be fully qualified `refs/heads/` or `refs/tags/` names satisfying the supported [Git ref-name rules](https://git-scm.com/docs/git-check-ref-format). Peeled `^{}` records must have a corresponding tag record. Duplicate records, null IDs, malformed input and out-of-scope refs are rejected. UTF-8 BOM, CRLF, record ordering and a missing final newline do not affect equality; input hashes still reflect exact bytes.

Two empty captures are inconclusive. One empty side produces missing or unexpected findings for all records on the other side. Output requires a new directory; existing evidence is never overwritten. Input errors produce `invalid_input` reports when the new output directory can be created; output failures or invalid CLI arguments may prevent report creation.

## Acceptance beyond refs

Matching advertised IDs does not establish complete object availability, default branch, LFS transfer, submodule availability, hidden refs, permissions, metadata, hooks or pipeline behavior. Verify those independently using the [migration runbook](migration-runbook.md). If history is intentionally rewritten, agree and document an alternate reconciliation mapping. This comparator never repairs, pushes, deletes or migrates existing repositories.
